## Detailed Changes By Theme

### 1. Server-wide powerhour scheduler (working tree, ported from ZH2.5 1.1.4)

**Files involved:** `pkg/opt/powerhour/powerhour.src`, `pkg/opt/powerhour/include/powerhour.inc` (new)

**Notable functional changes:**
- The old scheduler kept its start time in the local `started` and re-rolled `randomPH := Random(3)+1` on every one-minute tick. A restart mid-hour therefore left `PHH`/`PHC`/`PHS` set until the next weekly hour ended, and the end-of-hour bonus roll (`randomPH == 2` gives 1000/2000, else 1000/10000) tested a fresh random type, not the one that ran.
- New `powerhour.inc` holds every constant and helper: the type names (`PH_TypeName`), the global-property map, the schedule (`PH_GetStartTime`, `PH_GetSchedule`, `PH_SetSchedule`, `PH_ScheduleString`, `PH_SecondsUntilScheduled`, `PH_InWarningWindow`, `PH_NextSlot`, `PH_PreviousSlot`, `PH_LastSlot`), `PH_FormatDuration`, the scheduler process (`PH_FindScheduler`, `PH_EnsureScheduler`, `PH_NudgeScheduler`) and the personal-powerhour helpers (theme 4). It includes `include/client` and has no file-scope `var`.
- State lives in global properties: `PH_EndTime`, `PH_Source` (`scheduled` / `bonus` / `admin`), `PH_Pending`, `PH_PendingSource`, `PH_Request`, `PH_SecondChance`, `PH_StartTime` (absent = the original anchor 1543172400, Sunday 19:00 GMT), `PH_LastSlot` and `PH_SchedulerPID`. The flag names `PHH`/`PHC`/`PHS` are unchanged, so the crafting, gathering, bulk-order and skill-gain scripts that read them are untouched.
- `powerhour.src` loop, once a minute or when nudged (`Wait_For_Event(PH_TICK_SECONDS)`, queued events drained): an active hour ends when `systime >= PH_EndTime`. Otherwise, in order: an admin request (`PH_Request`, source `admin`); a pending bonus (`PH_SecondChance`, source `bonus`); the warning window for a slot not yet run (`PH_LastSlot != PH_NextSlot`, recorded before the 120-second warning sleep); and the catch-up (`MissedWeeklySlot`), all with source `scheduled` for the last two.
- `EndPowerhour` rolls the bonus only when `PH_Source == scheduled`: `Random(100) < 50` after half-resources, `< 10` otherwise.
- Catch-up: `MissedWeeklySlot` is true when `PH_LastSlot < PH_PreviousSlot(now)` and the slot is at most `PH_CATCHUP_SECONDS` (21600) old. An older slot is written off by setting `PH_LastSlot` to it.
- `RecoverAfterRestart` (review fixes folded in):
  - A flag with no end time gets `now + PH_DURATION`.
  - An active hour whose end passed more than `PH_STALE_END_SECONDS` (1800) before boot is cleared with `PH_ClearActive()`: no broadcast, no bonus roll.
  - The first run sets `PH_LastSlot` to the previous slot.
  - A pending warning is re-run directly with `StartPowerhour(pending, PH_PendingSource)`. Earlier drafts routed it through `PH_Request`, which made it an admin hour with no bonus roll and a different broadcast.
- Single instance: the scheduler checks `PH_FindScheduler()` and claims `PH_SchedulerPID` inside `Set_Critical(1)`. `PH_FindScheduler` also checks the process name contains `powerhour/powerhour`, to survive pid reuse after a restart.
- `StartPowerhour` sets `PH_Pending` and `PH_PendingSource`, broadcasts the 2-minute warning ("A random powerhour..." or, for admin, "A powerhour..."), sleeps `PH_WARNING_SECONDS`, then sets the flag, `PH_EndTime`, `PH_Source`, and clears the pending pair.

**Expected impact:** A server-wide powerhour survives a restart and ends on time. The bonus hour follows the 50% / 10% rule, only after a weekly hour. A weekly slot missed while another hour ran, or during downtime, starts within 6 hours. A stale hour after long downtime is cleared silently.

### 2. `.phadmin` (working tree, ported from ZH2.5 1.1.4)

**Files involved:** `pkg/opt/powerhour/textcmd/admin/phadmin.src` (new), `config/cmds.cfg`, `config/command_synopses.cfg`

**Notable functional changes:**
- Admin gump with four panels: status (active / pending / requested, next slot, server clock, bonus pending), start now (radio per type, refused while anything is active, pending or requested), active-time (minutes remaining, Apply, End now) and the weekly schedule (weekday 0-6, hour, minute; Save). The scheduler is started if it is found dead.
- It never changes state itself beyond requests and settings: Start writes `PH_Request` and nudges; Apply and End now write `PH_EndTime`; Save calls `PH_SetSchedule`. Every action is logged through `LogCommand`.
- Includes changed from ZH2.5's `:gumps:include/gumps` / `gumps_ex` to `:mdgumps:gumps` / `gumps_ex`; ZH3.0 has no `:gumps` package.
- Review fixes: Apply and End now set `PH_Source` to `admin` first, so a staff-ended or re-timed scheduled hour can't roll the bonus. Apply checks `PH_NudgeScheduler()` and refuses to broadcast the new end time when the scheduler is not running (End now already did). `PH_SetSchedule` only moves `PH_LastSlot` forward, so saving during the 2-minute warning can't un-mark the slot now starting and cause a second run.
- `config/cmds.cfg`: `DIR pkg/opt/powerhour/textcmd/admin` added under `CmdLevel Admin`.

**Expected impact:** Staff can start, re-time, end and reschedule server-wide powerhours in game. Each change to a running hour is broadcast.

### 3. `.ph` (working tree, ported from ZH2.5 1.1.4)

**Files involved:** `pkg/opt/powerhour/textcmd/player/ph.src`

**Notable functional changes:**
- Rebuilt on `powerhour.inc`. It shows the personal hour (type and minutes left) or, when there is none, eligibility through `PPH_IsEligible` / `PPH_SecondsUntilEligible`. It then shows the server-wide hour with `PH_FormatDuration(PH_SecondsRemaining)`, or "about to start" while `PH_Pending` is set, and the time to the next slot.
- `PPH_SecondsUntilEligible`: for a Sunday use (`use_weekday == 0`) the lock is `use_time + PH_WEEK + 1`. The old code showed the time to the following Sunday midnight, short by the time of day the hour started. (Theme 13 moves the rule and the countdown onto one `PPH_ResetTime`.)
- Countdowns drop zero parts.

**Expected impact:** `.ph` shows the time left on a server-wide powerhour, the 2-minute warning, and an accurate Sunday countdown.

### 4. Personal powerhour: resume, guards, shared cleanup (working tree)

**Files involved:** `pkg/opt/powerhour/textcmd/player/setph.src`, `pkg/opt/powerhour/resumeph.src`, `pkg/opt/powerhour/textcmd/test/resetph.src`, `scripts/misc/logon.src`, `pkg/opt/powerhour/include/powerhour.inc`

**Notable functional changes:**
- ZH3.0's resume model is kept. ZH2.5's `setph.src` was not copied: it ends the hour on logoff.
- **`resumeph.src` read `params[0]` and `params[1]`** (since `df69926`). EScript arrays are 1-based, so `who` was always an error and the script returned immediately. `logon.src` had already killed the sleeping `activateph`, so nothing ended the hour until a restart wiped the `#PPHx` flags. It now reads `params[1..3]`: who, remaining seconds, and the hour's `pph_use_time`.
- Guard from ZH2.5 1.1.4: `activateph` and `resumeph` remember `pph_use_time` and, after sleeping, return without touching anything if it changed (a `.resetph` followed by a new hour).
- `logon.src`:
  - It stores `resumeph`'s pid in `#PPHPid`, so `.resetph` and the next logon can kill it.
  - It keeps `pph_active_type` until the hour ends. It used to erase it right after resuming, so a second restart inside a resumed hour lost the rest of it while the week stayed used. It is erased only when the hour has already run out.
  - It uses `PH_DURATION`, `PPH_UseTime` and the `PPH_PROP_*` names instead of literals.
- Shared helpers in `powerhour.inc`:
  - `PPH_ClearFlags` erases the three type flags.
  - `PPH_Finish` sends "Your <type> Powerhour has ended!" if one is active, then erases the flags, `#SettingPH`, `#PPHPid` and `pph_active_type`.
  - `PPH_IsEligible` holds the one copy of the weekly rule.
- `setph.src` uses `PPH_ActiveType` / `PH_TypeName` / `PPH_SecondsRemaining` for the "already under the influence" lines and `PPH_IsEligible` for the weekly check. It drops its local `minute` / `hour` / `week` / `starttime` constants and `use math`, sets `pph_use_weekday` with `PH_WeekdayOf`, and ends with `PPH_Finish`. `resumeph.src` ends with `PPH_Finish` too.
- `.resetph` erases `pph_active_type` (it was left behind, so the next logon would try to resume a reset hour) and uses `PPH_ClearFlags` and the shared property names.
- Message wording is now `PH_TypeName`: "Hunting", "Half-resources", "Double skillgain" (was "Half-Resources", "Double-Skillgain").

**Expected impact:** A personal powerhour ends on time after a relog, survives more than one restart within the hour, and is not cut short by an old timer after a reset. The weekly rule is unchanged.

### 5. Classes: gear sweep, stored class levels, tooltip hook (working tree)

**Files involved:** `scripts/include/classes.inc`, `pkg/packethooks/megacliloc/itemdata.src`

**Notable functional changes:**
- `IsFromThatClasse` no longer calls `unequipRestrictedItems` (two `SleepMS(5)` per worn item) when it finds a class. `AssignClasse` no longer calls it per class either; it calls it once after every class is stamped (ZH2.5 1.1.4's shape). Every path that recomputes classes goes through `AssignClasse`: login (`playermanager.src`), `:summoning:checkclasse` every 10 minutes, `.showclasse`, `.class`, `.setclass`, the class boost stones and the RP stone. Because the sweep is no longer conditional on a class being found, classless characters are now swept at login too.
- New `HeldOrLiveClasseLevel( who, classeid, flags... )`: for a player it returns `CInt(GetObjProperty(who, classeid))`, the level `AssignClasse` stored. For an NPC it returns the live `IsFromThatClasse` scan. All ten `Is<Class>()` predicates go through it with their old co-skill flags. That covers ~120 call sites in combat, spells, healing, songs, guilds and tooltips, which used to re-scan all 50 skills per call.
- `itemdata.src` (the megacliloc tooltip hook): all 12 class checks read stored levels through `HighestHeldClasseLevel(who, {...})`. The four Bardic/Magic Efficiency checks are also nested under their property test. With no short-circuit, `BE && (IsBard(who) || ...)` used to run every class check on every armour and weapon tooltip.

**Expected impact:** Combat, spells and tooltips stop recounting skills and re-checking gear on every class lookup. A newly reached class level takes effect at the next class check: login, `.showclasse`, or within 10 minutes. Spell and combat effects used to see it immediately.

### 6. Classes: primary class, stat tables, stat floor, Powerplayer (working tree)

**Files involved:** `scripts/include/classes.inc`, `scripts/include/skillpoints.inc`

**Notable functional changes:**
- New `GetPrimaryClasseId( who )` returns the held class with the highest level, ties going to `GetClasseIds()` order. `GetClass` returns it (it returned the first held class in list order), and `IsProhibitedByClasse` branches on it instead of the first `GetObjProperty( who, CLASSEID_X )` hit. A single-class character is unchanged.
- New `HighestHeldClasseLevel( who, classeids )`. `HaveStatAffinity` and `HaveStatDifficulty` return it instead of the first held class in list order, which reverses the 3.1.3 note that "a character holding two classes now takes the first match". `GetStatPointsMultiplier` now lets the higher of affinity and difficulty decide (a tie favours affinity); before, any affinity beat any difficulty. ZH3.0's 2026-10-07 stat table is kept. ZH2.5 1.1.4's table differs (Bard and Mystic Archer two fast stats).
- `skillpoints.inc`: new `ClassStatGainAmount( who, attributeid, amount )` scales the dice amount by `ClassStatGainMultiplier` and never returns below 1. This is defensive only. The smallest advance in `skillsdef.cfg` (the file `GetSkillConfigElem` reads) is 2d2 and the lowest multiplier 0.4, so `Cint(2*0.4+0.5)` is already 1. The 1d3 / 1d5 / 1d8 advances are in `attributes.cfg`, which this path doesn't read.
- Powerplayer: `GetClasseIdForSkill` skips `CLASSEID_POWERPLAYER` entirely. The 3.1.3 rule allowed it on Forensics, Throwing, Snooping and Detecting Hidden. `IsSpecialisedIn` therefore returns 0 for a Powerplayer on every skill: no gain multiplier (`GetSkillPointsMultiplier`), no second roll (`shilhook.src`), no success bonus. The skill-wide Powerplayer multiplier in `AwardSkillPoints` was ×1.1 / ×1.2 / ×1.3 at levels 3-5 here; theme 10 replaces it with ZH2.5's later curve.

**Expected impact:** Powerplayers lose the class bonus on those four skills. Dual-class characters are judged by their stronger class for gear rules and stat growth. No change for single-class characters.

### 7. `.classbonusinfo` (working tree, adapted from ZH2.5 1.1.4)

**Files involved:** `pkg/opt/alryc/textcmd/test/classbonusinfo.src` (new), `config/command_synopses.cfg`

**Notable functional changes:**
- Developer command (`textcmd/test`, CmdLevel 5). Levels 1-3 add the remake's bell-curve noise (multiplier from 8 dice, multiplier from 2 dice, additive noise as wide as the score spread). Level 4 deviates from the remake: it plays a random affordable card 3 times in 4 and otherwise discards a random card, because choosing uniformly among all legal moves almost always discarded.
